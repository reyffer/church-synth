# Church Synth: notes for Claude

Read SPEC.md first: it is the source of truth for features and holds the decisions log.

## Who / what
- Owner: Reyffer (church FOH engineer, London). Live use: MainStage on an M1 MacBook Pro 16 GB, several instances per concert. Sound design on a Windows PC (VST3).
- Goal: Pigments-like architecture, lighter on CPU, never glitches live.

## Hard rules
- **Audio thread:** no allocation, locks, file I/O, logging or exceptions. All buffers are fixed-size (see `kBlock`, `kMaxVoices`, `kMaxUnison`).
- **Parameter IDs are permanent.** Never rename or remove an ID in `source/plugin/Parameters.cpp`; saved MainStage concerts depend on them. Add new IDs instead. Macros 1–4 must stay the first parameters.
- **Original code only.** Surge XT (GPL) may be read as a DSP reference, never copied. Never copy Arturia content (wavetables, noises, presets, artwork) or use their product/effect names in the UI. Our names: Drive filter (Rage-like), Allpass filter (Ripple-like), Erode (Corroder-like), Vintage Chorus (Juno-style), Vintage Flanger.
- **Factory content order is permanent.** `kWavetableList` / `kNoiseList` in `ContentFactory.cpp` are indexed by host parameters: append only, never reorder or remove. Content can be retuned, but don't change a table's character so much that saved presets sound wrong.
- **Never put `SynthCore`, `Voice` or the processor on the stack** (they're ~1 MB; Windows' default stack is 1 MB). Use `std::make_unique`.
- DSP core (`source/dsp`) stays JUCE-free so it can be tested and benchmarked anywhere.
- Every DSP change: `ctest` passes and `cs_bench` doesn't regress without a reason.

## Architecture
- `SynthCore` → 16 `Voice`s → per voice: 2 engine slots (each `AnalogEngine`, `WavetableEngine`, `OrganEngine` or `SectionEngine`) + `UtilityEngine` → filter-mix split → 2 `MultiFilter`s (15 models incl. `ClassicFilter`; series↔parallel or Split) → amp `Envelope` → pan → buses Main / FX A / FX B / Direct → `FxRack` (in `SynthCore::renderChunk`; `fx_on` off = dry with a 20 ms crossfade) → master volume × 2 (+6 dB output stage) → width / mono check → peak limiter at −1 dBFS. When idle (no voice, output < −100 dBFS for 0.25 s, seq off) `SynthCore::render` skips everything until a note-on. Utility osc can bypass the filters (post buffer → its routed bus).
- Filter models: `MultiFilter.h` (controls per model documented at the top and in SPEC §4.4). Drive uses `AutoGainSaturator` (MathUtil.h) before and after the filter so it changes character, not level. `FilterType` order is append-only. Feedback paths inside filters must stay bounded under audio-rate FM (soft-clip them).
- Cross-mod: an engine's modulator can be the other engine's pre-volume output; the source engine renders first (mutual cross-mod uses the previous 16-sample block).
- Content (`Content.h/.cpp`, `ContentFactory.cpp`): 40 wavetables + 34 noises synthesised in code, mip-mapped (11 levels), generated lazily and cached process-wide. The plugin's `Loader` thread resolves selections and user files into atomic pointers; the audio thread only reads pointers.
- User files are copied to `Documents/Church Synth/Wavetables|Noises` and referenced by file name in the plugin state.
- Modulation (`ModSources.h/.cpp`, `ModMatrix.h/.cpp`): per control block each voice computes only the sources something uses (`GlobalMod::used`), copies `SynthParams` into `local`, adds route offsets in each destination's normalised (knob) space, then renders with `local`. LFO/Function/Random in Mono/Legato/Free-running retrig use a single global instance in `SynthCore`; Poly Kbd uses per-voice instances. Source *settings* (e.g. LFO rate) read last block's modulated values.
- Destinations use host parameter IDs; routes are saved by source name + destination ID in the plugin state (`ROUTES` child) and handed to the audio thread through a seqlock. Function/remap preset lists and sync divisions are append-only.
- FX (`source/dsp/fx`): `FxRack` runs buses A / B / Aux (3 slots each) on the summed voice buses; `Effects.cpp` holds the 21 effects (Rotary 20, Organ Scanner 21 appended last) and the `kFxInfo` table (names, controls, defaults). `FxType` order is append-only. Effects are allocated on the message thread by `FxHost` (plugin timer / prepareToPlay / state load), published through atomic pointers and freed two render epochs later; the rack skips a slot whose effect doesn't match its type yet. FX modulation destinations are `global` (evaluated once per chunk in `SynthCore`). Echo/reverb/chorus effects use equal-power Dry/Wet; a test keeps default settings within ±1.5 dB.
- Seq/Arp (`SeqArp.h/.cpp`): owned by `SynthCore`. With `seq.on`, keys go to the sequencer and it plays voices through `SeqSink` (sample-accurate: `SynthCore::render` renders up to each event). Timing is kept in steps; host playing → follows ppq. The pattern (`SeqPattern`) is plugin state (`SEQ` child) handed over through a seqlock; random offsets are hashed from a seed (`seqResolve`), so the editor can preview them. Track, scale, auto-regen and divider lists are append-only.
- Plugin state (`createStateTree` / `restoreStateTree` in the processor) is one ValueTree: APVTS params + `ROUTES` + `SEQ` + `FUNCS` (drawn function shapes) + `MIDIMAP` + macro names + user file names + preset name. Presets (`PresetManager`, `.csp` XML) are the same tree without `MIDIMAP`; factory presets/patterns/FX presets are built in code (`FactoryPresets.cpp`, `PresetBuilder` sets real-unit values by param ID). Undo = snapshots of that tree taken on parameter gesture ends from the editor and on explicit `checkpoint()` calls.
- Editor (`source/plugin/ui/`): drawn at 1280×800 and scaled (fixed aspect). `UiContext` holds the selected mod source and route helpers; `Knob`/`Pill`/`Toggle`/`Stepper` bind to params. Pages: `SynthPage`, `FxPage`, `SeqPage`; `ModStrip` + `ModTabs`; `Header` (top bar, footer); `PresetBrowser`. Live values come from `SynthCore::uiSource` atomics, published only while an editor is open. The state test can screenshot every page (`cs_state_test --snapshot <dir> [preset]`) and render the factory set (`--render-presets <dir>`, `--preset-report`).
- Factory presets are level-matched (peak ≈ −4 dBFS for a 4-note chord, ≈ −7 dBFS for mono). After changing DSP gain staging run `cs_state_test --level-report`: it plays 12 dB down (below the limiter) and prints each preset's true peak and the `master_vol` that hits the target; `--preset-report` shows the post-limiter levels.
- Preset packs (`packs/`): downloadable user presets, built in code with the same helpers as the factory set (`source/plugin/PresetHelpers.h`), compiled only into `cs_state_test`. `cs_state_test --export-pack <dir>` writes the `.csp` files, level-matched (three quiet runs, loudest kept); `--render-pack <dir> <wavdir> [pack] [sweep]` renders an audition WAV per preset (`sweep`: single notes C1–C7 + three velocities, for pianos and anything velocity/key-tracked). `PresetBuilder::errors` lists unknown IDs / menu items / routes; the state test fails on any. Each pack has a tag table (`pack1Tags`) and a notes table (`pack1Notes`, own file); the state test fails on a pack preset without either. Texture presets are levelled for one held note (−7 dBFS) and Texture/FX are measured over 10 s. Unison with random phases makes a preset's peak vary run to run; for pianos (Pack 15) the wavetable Unison Phase is 0 so the strings start together. Packs are delivered one per round (SPEC decisions log has the order); factory tags are in `factoryPresetTags` (FactoryPresets.cpp). User tag edits live in `Documents/Church Synth/Preset Tags.xml` keyed by `PresetInfo::key()`.
- Threading: `cs_state_test --stress-threads [s] [mask]` (in ctest) plays audio while other threads set parameters and save/load state; run it in a ThreadSanitizer build when touching anything shared. `--fuzz` / `--fuzz-dynamic` hunt for non-finite output. Anything that can be swapped while a note plays (noise samples, wavetables, effects) must tolerate the swap mid-note.
- Help and notes: every parameter needs a help-bar text (`ui/Help.cpp`, regex rules by ID; the state test checks) and every factory preset needs notes (`FactoryNotes.cpp`) and tags.
- Effects tuned against reference renders (v0.4, SPEC decisions log; project docs FX-ANALYSIS.md / FX-ANALYSIS-TOOLS.md): `cs_fxcli` (tools/fxcli.cpp, DSP-only) runs one effect on raw float audio, `tools/fx_analysis/fxmeasure.py` measures taps / coherence / side-mid / RT60 / tilt / pitch smear against the references, `cs_state_test --render-fx <signals> <out>` writes WAVs. `ChurchSynthProcessor::kStateVersion` (5) + `migrateState()` fill new FX controls in states saved before them (PresetBuilder trees carry the current version, so factory/pack builds aren't migrated); bump it and extend `migrateState` whenever a new control's 0 would change an old preset. User FX presets (.csfx) carry a `v2` marker for the same reason.
- Learning aids (v0.3): sound LEDs (`ui::SoundLed`, `SynthCore::uiMeter`, `Meter` enum in Voice.h; engines fill per-part peaks only when passed a meter pointer, the voice scales by the amp envelope; the LED timer reads with `exchange(0)` and skips while hidden, since Analog and Wavetable views of one engine share meters); travelling dots (`SynthCore::uiVoice`: env position = stage + progress from `Envelope::getPosition`, LFO phase, function position); mod links overlay (`ModLinksOverlay` in PluginEditor.cpp, recomputed each tick, repainted only when its key changes) and `UiContext::focusedDest` (knob click lights its sources). `visibleInEditor()` instead of `isShowing()` so snapshots work. `cs_state_test --snapshot` also writes `ui_live_*` (notes held while the editor ticks via `tickForTest`) and browser folder views.
- Mod connections (v0.6.1): no mod-edit mode. `ui::ModTarget` (Widgets.h) is anything a source can be dropped on (`Knob`, `FxMenu`); `UiContext::draggingSource` (set by the editor's `dragOperationStarted/Ended`) lights all targets; a drop makes a 0 route and calls `ctx.openWheels`. `ui::ModWheels` (ModWheels.cpp) is an always-on-top child of the Root, hit-testing only its panel; `tick()` (30 Hz, from Root) polls the component under the mouse for the 0.5 s open delay / 0.27 s close grace. `UiContext::modulatedValue` gives a parameter's value with its routes (FX switches, Rotary lamp). Test hooks: `openModWheelsForTest`, `setDraggingSourceForTest` (snapshots `ui_live_drag_targets`, `ui_live_wheels_*`, `ui_live_fx_rotary_*`, `ui_live_organ_lamp`).
- Editor details worth knowing: a click anywhere but a mod target or the mod strip ends the tile's link view and closes the mod wheels (root `mouseDown` via `addMouseListener`); discrete FX controls are listed in `fxChoices` (FxPage.cpp) and shown as menus; `EqGraph` computes the Param EQ curve from the real effect's impulse response; `EnvDisplay` points are draggable. The logo is `resources/images/lotus.png` (white alpha mask, tinted when drawn).
- Organ engine (v0.5, `OrganEngine.h`, SPEC §3.5 "Organ as built"): 91 tonewheels (gear-ratio table in `organ::WheelTable`), 9 drawbar slots + percussion + 9 leakage slots per voice, phases from `GlobalMod::organClock`; percussion level is shared per engine slot in `SynthCore::tickOrgan` and restarted in `playNoteOn` only when `numHeld == 0`; `Voice::release` / `retarget` call the organ's `noteOff` / `retrigger` (contacts and click). Params `e[12]_org_*` are appended at the end of `Parameters.cpp`; the editor's `OrganView` (SynthPage.cpp) uses `Knob::setDrawbar` (a vertical drawbar look on the normal knob, so mod drop / rings / MIDI learn / help all work). Preset helpers `tonewheel()`, `percussion()`, `organFx()` in PresetHelpers.h. `EngineType` and `kEngineTypes` are append-only; engine types with no unison must be excluded from the chord-arp checks (`hasChordEngine`, `updateSeqState`). Expression (CC11) defaults to 1.0.
- Section engine (v0.6, `SectionEngine.h`, SPEC §3.5 "Section as built"): up to 8 `BlepOscillator` players per note (saw / narrowing pulse), seeded from the key (`seatPlayers`), per-player 12 dB low-pass and amp, one noise band-pass, stereo body bank (`sectiondsp::Bodies`, shapes normalised in a static built on first use from `setSampleRate`). `Voice::retarget` calls `restrike()` (retrigger) or `slur()` (legato). Params `e[12]_sec_*` appended after the organ's; `SectionView` + `SeatingView` in SynthPage.cpp. Preset helpers `ensemble()`, `sec()`, `wheelDynamics()`. Packs `Pack 4 II` / `Pack 5 II` (packs/Pack4II*, Pack5II*), names end in "II". New engine types go at the END of `Voice` and their `render` is `CS_NOINLINE` (MathUtil.h): inlining them slowed the wavetable path ~5 %. The DSP namespace is `sectiondsp` (`section` / `ensemble` clash with preset helpers).
- `cs_state_test --render-presets <dir> [name filter]` renders an organ phrase (chord, detached then legato line, mod wheel to fast rotary and back) for presets named Tonewheel…
- Control rate = 16 samples (pitch, filter coefficients, envelope points); audio rate for oscillators, FM and filtering.
- Oscillators use polyBLEP/polyBLAMP with one sample of latency, so hard sync is band-limited exactly.
- The Amp Mod gain (velocity / tremolo / gates) is smoothed per sample (~2 ms) so legato velocity changes and stepped modulators don't click.
- Voice stealing does a 3 ms fade before the new note starts. Retriggering a sounding voice never resets oscillator phase.

## Performance notes
- Benchmark baseline (x86 container, M1 numbers are in CI): analog pad 8 voices ≈ 5.5 %, wavetable pad ≈ 3.5 %, worst case ≈ 29 % of one core. Content generation for everything ≈ 2.4 s total, but only what's selected is generated.
- Organ: 8 notes ≈ 46 µs / 128-sample block (pad case ≈ 240 µs); bench cases `organ_8voices`, `organ_all_out_16voices`.
- Section: 8 notes × 6 players ≈ 120 µs (strings) / 135 µs (brass); bench cases `section_strings_8voices`, `section_brass_8voices`. For a fair gate against an older version build both benches with the same flags and run them interleaved (min and median of 5).
- Seq/Arp cost is negligible (arp 16ths + delay + reverb on a supersaw ≈ 3 % of a core).
- FX cost (same container): chorus + delay + reverb ≈ 1.5 % of a core; all 9 slots busy ≈ 8 %. The bench has `pad_fx_*` cases.
- Memory (`cs_state_test --mem-report [n]`, x86 Linux): each instance ≈ 1.5 MB core + its effects (delays ≈ 1 MB, reverb/shimmer ≈ 0.7 MB, the rest ≈ 0); factory content is shared process-wide and generated only when selected (all 40 tables ≈ 62 MB, all 34 noises ≈ 30 MB).
- Planned optimisation: process 4 unison sub-voices with SIMD (NEON/SSE), skip silent engines entirely (already done), cheaper sine.
